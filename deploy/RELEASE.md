# Release 21 — acceptance gates

Informational mode only. No live sales, account registration, wholesale submissions or email. Do not use a production database for initial testing.

## Local / GitHub CI
1. Install Node 22, Docker and Terraform >=1.6. From project root run `npm install`, `npm test`, `docker compose up -d db` (check service name in compose.yaml), configure DATABASE_URL and APP_ORIGIN from .env.example, then `npm run migrate`, `npm run db:verify`, `npm run build`, `npm run typecheck`.
2. Start with `npm start` in a separate terminal with the same environment. Run `npm run smoke` and `npm run release:check`. Set SMOKE_ORIGIN to the exact APP_ORIGIN if not localhost. These probes intentionally verify disabled endpoints; never run against an enabled commercial deployment.
3. Push to a private GitHub repository. Require successful Validate and Terraform checks before merging. Review dependency audit and retain build logs. Commit a reviewed package-lock.json generated by npm; switch CI to npm ci once committed.
4. Follow deploy/terraform/README.md for staging. Run terraform init and validate, then review plan and costs before any apply. Do not apply without approval. Repeat smoke and release checks against staging HTTPS.
5. Before apex DNS change: verify actual pages on mobile and desktop, content and legal disclosures, TLS, monitoring, backup restore, rollback image digest and domain ownership. Keep sales disabled.

## Commercial launch — separate gate
MFA, refund workflow, end-to-end payment and fulfillment, food regulatory approvals, product labels, traceability and recall drills, verified email delivery and security review remain mandatory. Existing test checkout deliberately rejects NODE_ENV=production; do not bypass this guard to launch.

## Rollback
Retain previous known-good image digest and ECS task revision. Restore prior task revision if application checks fail; do not automatically reverse database migrations. Review compatibility and restore from verified backup only with explicit approval and a data-loss assessment.
