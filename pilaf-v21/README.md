# THE BEST PILAF 3.0
Development source, not a deployed store. Requires Node 22, npm and Docker Compose.
1. Copy `.env.example` to `.env`; set a strong URL-safe local password in both variables.
2. `docker compose up -d`
3. `npm install`
4. `npm run dev` and open http://localhost:3000.
5. `npm run typecheck` and `npm run build` before deployment.

21 migrated pages, static trusted HTML content inside Next.js React routes, browser basket, PostgreSQL initial schema, read-only catalog API `/api/catalog`, database health `/api/health`, deliberately disabled POST `/api/orders`. Storefront catalog remains static; API integration is next. No customer authentication, payment processing, order creation, inventory mutations or admin UI yet. No real prices or compliance claims. SQL initializes only a new database volume. Production requires migration tooling, security review, verified product details and regulatory readiness. Illustrations retained from v2. No secrets included. Dependency installation and runtime build have not been verified in the authoring environment.

## Version 4: administration
Set ADMIN_PASSWORD in .env to a random ASCII password of at least 24 characters (e.g. `openssl rand -hex 32`). Open /admin. The password is held in page memory and sent with each API request; use only localhost or HTTPS. The API rejects missing credentials and disables response caching. Product names, descriptions, publication flags, SKU prices in cents and stock can be edited. Orders, customers and wholesale inquiries are read-only, latest 100 each. Public storefront still uses static content; catalog API reflects database changes. Sales remain disabled. Before public deployment replace shared password with individual accounts, MFA, rate limiting and audit logs. No dependency installation or database integration test has been performed in this environment.

## Version 15 — administrative access
Run all migrations before starting. The shared ADMIN_PASSWORD no longer works. Provision an individual account using `npm run admin:create -- alice owner` with DATABASE_URL and NEW_ADMIN_PASSWORD supplied securely in the process environment. Use a unique randomly generated ASCII password of at least 24 characters; unset the provisioning secret afterwards. Supported provisioned roles: owner, shipping, manufacturing, wholesale, finance. Existing CI smoke tests may require updating administrator provisioning. No live sales.

## Version 16 — lot traceability
Apply migration 010 using npm run migrate. Existing SKU stock is not automatically converted into traceable lots; reconcile it before testing. Manufacturing API accepts action `release` with string batch_id, sku_id, quantity (number of packs). Batch units represent individual cans. Only reviewed, unexpired batches may be released. GET returns finishedLots, skus and affectedOrders. Order insertion allocates eligible lots FEFO; cancellation releases allocations; shipment requires complete eligible allocations. Legacy orders without allocations cannot ship. SKU stock is a secondary counter and may overstate available stock after recall or expiry; checkout rejects insufficient eligible lots. Admin stock edits are disabled (submitted stock must match current stock). Recall does not automatically refund or notify customers. Concurrent operations can deadlock and require retry. Database integration tests, release UI, inventory reconciliation, notifications, MFA and refunds remain outstanding. Do not enable live sales.

Use Node 22 and Docker Compose. For a **new empty database only**:
1. Copy `.env.example` to `.env`; choose a local password and update DATABASE_URL accordingly (URL-encode special characters).
